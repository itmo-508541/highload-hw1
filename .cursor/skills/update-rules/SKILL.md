# Обновление CHANGELOG, правила, README

## Когда применять
- После любых заметных изменений в коде/инфраструктуре/БД/документации
- Когда пользователь просит обновить правила/логи/README или “подведи итоги изменений”

## Инструкции
1) **CHANGELOG.md**
   - Прочитать `CHANGELOG.md`, чтобы понять текущий формат последних записей.
   - Добавить новую запись **в раздел Unreleased**.
   - Описать: что сделано, какие файлы изменены/созданы (списком путей), важные решения/ограничения.
   - Даты/заголовки соблюдать в стиле существующего файла.

2) **.cursor/rules/general-rules.mdc**
   - Проверить, не изменился ли технологический стек/договорённости команды/правила работы.
   - Если изменения затрагивают правила (например: новые обязательные команды, новый сервис, новые ограничения) — обновить `/.cursor/rules/general-rules.mdc`.
   - Не добавлять лишней воды: только то, что реально нужно соблюдать.

3) **README.md**
   - Проверить, не устарели ли инструкции запуска/тестов/переменных окружения/важные ссылки.
   - Если изменения затрагивают запуск/настройку/документацию — обновить `/README.md` минимально необходимыми правками.

## Мини-чеклист качества
- `CHANGELOG.md` дополнен, формат сохранён
- `general-rules.mdc` обновлён только при реальной необходимости
- `README.md` актуален после изменений
