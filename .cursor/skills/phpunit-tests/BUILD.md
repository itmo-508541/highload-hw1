# BUILD — консолидация Model Knowledge Patch

Эта инструкция описывает процесс создания/обновления консолидированного файла (например, `PHPUnit13-full.md`) из набора дельта-патчей.

## Когда запускать

После обновления любого дельта-файла (`PHPUnit9.md` … `PHPUnit13.md`) или при переходе на новую мажорную версию.

## Входные данные

Все дельта-патчи от версии 9 до текущей:

- `PHPUnit9.md`
- `PHPUnit10.md`
- `PHPUnit11.md`
- `PHPUnit12.md`
- `PHPUnit13.md`

## Выходной файл

`PHPUnit13-full.md` — единый консолидированный Knowledge Patch, готовый к подключению в скилл.

При переходе на PHPUnit 14: выходной файл станет `PHPUnit14-full.md`.

## Структура выходного файла

```
# PHPUnit 13 — Model Knowledge Patch

## Banned calls → replacements

<единая таблица>

## Assertions the model may not know about

<единый список>

## Behavior traps

<единый список>

## Test structure

<единый список>
```

Файл начинается с заголовка первого уровня и сразу переходит к контенту. Блок с принципами составления **не включать** — контекст подключения обеспечивает скилл.

## Правила консолидации

### Статусы: записывать только текущее состояние

Проследи цепочку статусов каждого API через все версии и запиши **только финальное состояние** для целевой версии:

| Цепочка | Что писать |
|---|---|
| soft deprecated (v9) → hard deprecated (v11) → removed (v13) | **removed** |
| soft deprecated (v12) → без изменений в v13 | **soft deprecated, no runtime warning** |
| hard deprecated (v11) → без изменений в v13 | **hard deprecated** |
| deprecated (v9) → не упомянут как removed | **deprecated** (оставить — это ловушка для модели) |

**Не указывать номер версии**, в которой произошло изменение. Не писать "since 9" или "removed in 12".

### Противоречия: побеждает последняя версия

Если поведение изменилось между версиями, записывать только актуальное для целевой версии:

- `readonly class` cannot be doubled (v10) → CAN be doubled (v11+) → **писать "can be doubled"**
- `Data providers must be public static` (v10 soft) → removed non-static (v11) → **писать "removed, fatal"** (в Banned calls)

### Assertions: кумулятивно

Собрать **все** assertions из всех версий (9→13), которые модель может не знать. Это единственная секция, где важен полный набор. Удалить только те, что сами были deprecated/removed в последующих версиях.

### Behavior traps: только актуальные

Включать только те ловушки, которые всё ещё действуют в целевой версии. Если trap был исправлен или поведение изменилось — убрать.

### Test structure: кумулятивно

Собрать все актуальные структурные рекомендации из всех версий.

## Верификация

После генерации проверь:

1. **Нет дублей** — одна и та же пара «banned → replacement» не встречается дважды.
2. **Нет противоречий** — файл не утверждает взаимоисключающие вещи.
3. **Полнота** — количество пунктов в full-файле ≥ количества пунктов в дельта-файле текущей версии.
4. **Нет номеров версий** — в тексте не упоминаются конкретные версии PHPUnit (кроме заголовка и требования к PHP).

## Порядок действий

1. Прочитай все дельта-файлы (`PHPUnit9.md` … `PHPUnit13.md`).
2. Для каждого пункта из `Banned calls → replacements` — определи финальный статус, запиши один раз.
3. Собери все assertions из всех файлов, удали устаревшие.
4. Собери behavior traps, оставь только актуальные.
5. Собери test structure, оставь только актуальные.
6. Запиши результат в `PHPUnit13-full.md`.
7. Выполни верификацию (см. выше).
