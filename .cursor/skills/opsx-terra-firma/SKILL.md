Создать `terra.md` в каталоге OpenSpec change — карту территории, исследованной
AI-агентом Эксперта при планировании. Файл передаёт контекст обнаружения
(прочитанные файлы, увиденные паттерны, факты о коде) от AI-агента Эксперта
к AI-агенту Разработчика при парном программировании.

`terra.md` — опциональный файл, не входящий в цепочку артефактов OpenSpec.
Если Эксперт не создаёт terra, apply работает как обычно.

**Input:** необязательное имя change после `/opsx-terra-firma`
(например `/opsx-terra-firma add-auth`). Если опущено — вывести из контекста
чата (только что завершённое планирование) или спросить.

Всегда объяви: «Using change: \<name\>» и как переопределить
(`/opsx-terra-firma <other>`).

## Guardrails

- Создавать `terra.md` разрешено **только** этой команде. Вне
  `/opsx-terra-firma` файл `terra.md` не создавать и не менять.
- Не изменять `.cursor/skills/openspec-*` и `.cursor/commands/opsx-apply.md`.
- Не делать поиск по репозиторию для наполнения terra. Источник данных —
  контекстное окно AI-агента (то, что уже знает из сессии планирования).
- Не запрашивать внешние данные, не делать `git log` / `git diff`.
- Коммит не создавать — Эксперт видит diff в UI Cursor.

## Steps

### 1. Выбрать change

1. Если имя задано — использовать его.
2. Если опущено — вывести из контекста чата (только что завершённое
   планирование, упомянутый change).
3. Если неоднозначно — запустить `openspec list --json` и спросить Эксперта.

### 2. Проверить предусловие

Проверить наличие `tasks.md` в каталоге change файловой системой.

- **`tasks.md` существует** → продолжить.
- **`tasks.md` не существует** → предупреждение: «Планирование не завершено:
  tasks.md не найден в каталоге change. Создайте tasks.md командой
  `/opsx-continue` перед запуском `/opsx-terra-firma`.» **Остановиться.**
  Terra не создавать.

### 3. Прочитать артефакты change

Прочитать все существующие артефакты change (proposal.md, specs, design.md,
tasks.md) для полноты контекста. Это не поиск по репозиторию — это чтение
файлов change, которые агент уже знает.

### 4. Сформировать terra.md

Сформировать содержимое `terra.md` из контекстного окна — из того, что
AI-агент уже знает о кодовой базе в результате сессии планирования.

**Критерии содержания:**

- **Достаточность**: для каждой задачи из `tasks.md` AI-агент Разработчика
  должен знать из terra.md, какие файлы открыть, какому паттерну следовать
  и что находится рядом с точкой изменения — без поисковых операций по
  репозиторию.
- **Необходимость**: каждое утверждение в terra.md должно устранять конкретный
  cache miss. Если удаление утверждения не заставит AI-агента Разработчика
  искать, угадывать или ошибаться — оно лишнее.

**Четыре секции:**

1. **Карта файлов** — таблица: путь, роль файла *в этом change*, действие
   (создать / изменить / читать как образец / не трогать). Включить все файлы,
   которые агент знает как относящиеся к change.
2. **Наблюдения** — конкретные факты о коде, обнаруженные при планировании
   и повлиявшие на решения в design. Структуры данных, форматы, соглашения,
   интеграционные точки.
3. **Образцы** — для каждого паттерна, которому change должен следовать:
   конкретный файл-образец и что именно в нём является паттерном.
4. **Навигация** — порядок чтения файлов от общего к частному. Для каждого
   файла — что даёт его чтение. Подсказка AI-агенту Разработчика (или
   человеку), если нужно углубиться в контекст.

### 5. Записать terra.md

Записать файл в `<changeRoot>/terra.md` (рядом с proposal.md, design.md,
tasks.md).

Коммит **не** создавать — Эксперт видит diff в UI и сам решает, когда
коммитить.

### 6. Итог

Сообщить: change, количество файлов в карте, количество наблюдений, количество
образцов. Напомнить, что Эксперт должен включить terra.md в коммит перед
handoff Разработчику.

## Формат `terra.md`

```markdown
## Карта файлов

| Файл | Роль в change | Действие |
|------|---------------|----------|
| `path/to/file` | описание роли | создать / изменить / образец / не трогать |

## Наблюдения

- Факт о коде, обнаруженный при планировании и повлиявший на design.
- Ещё факт.

## Образцы

- `path/to/example` — что именно в нём является паттерном для этого change.

## Навигация

1. `path/first` → что даёт чтение этого файла
2. `path/second` → что даёт чтение этого файла
```
