## Purpose

Коммитируемый индекс, связывающий OpenSpec-тематики (specs) с файлами реализации,
чтобы AI-агент мог перейти от домена к исходному коду за минимальное число операций чтения.

## ADDED Requirements

### Requirement: Трёхуровневая навигация — домены → тематики → файлы
Индекс MUST предоставлять три уровня навигации:
1. Домен — логическая группа тематик с кратким описанием.
2. Тематика — соответствует одному `openspec/specs/<topic>/spec.md`.
3. Файлы реализации — конкретные исходники, тесты и entry points.

Связь доменов и тематик — M:N: домен содержит несколько тематик, тематика
входит в несколько доменов.

#### Scenario: Агент находит файлы по домену
- **WHEN** агент читает INDEX.md и выбирает домен
- **THEN** он видит список тематик этого домена и может прочитать topic-файл
  для получения списка реализующих файлов и их ролей

#### Scenario: Тематика принадлежит нескольким доменам
- **WHEN** одна тематика логически относится к двум и более доменам
- **THEN** она указана в строке каждого из этих доменов в INDEX.md

### Requirement: INDEX.md — компактная точка входа
INDEX.md MUST содержать:
- Таблицу доменов (domain, description, topics).
- Таблицу тематик (topic, spec path, summary — краткое описание в свободной форме).

Объём INDEX.md НЕ MUST превышать 200 строк.

#### Scenario: Агент ориентируется по INDEX.md
- **WHEN** агент читает INDEX.md
- **THEN** он получает полный перечень доменов и тематик за одно чтение файла

### Requirement: Per-topic YAML — детальный маппинг реализации
Для каждой тематики MUST существовать файл `topics/<topic>.yaml`,
содержащий:
- `topic` — идентификатор (совпадает с именем каталога в specs).
- `spec` — путь к spec.md относительно корня репо.
- `summary` — краткое описание (свободный текст).
- `files` — список объектов `{path, role}`, где role — короткий свободный текст.
- `entry_points` — список объектов `{type, path|trigger, handler}`.
- `tests` — список объектов `{path, role}`.

#### Scenario: Агент получает реализацию конкретной тематики
- **WHEN** агент читает `topics/<topic>.yaml`
- **THEN** он видит все файлы, реализующие Requirements этой тематики,
  с описанием роли каждого файла

#### Scenario: Entry points типизированы
- **WHEN** файл содержит entry_points
- **THEN** каждый entry point имеет `type` из набора: route, command, event, cron, message

### Requirement: Агент — read-only потребитель
AI-агент MUST использовать индекс только для чтения. Обновление индекса —
ответственность Архиватора (человека).

#### Scenario: Агент не модифицирует индекс
- **WHEN** агент работает с проектом вне процедуры archive
- **THEN** он НЕ создаёт и НЕ изменяет файлы в директории скилла capability-index

### Requirement: Инкрементальное обновление при archive
При archive Архиватор MUST обновлять только topic-файлы тех тематик,
чьи spec.md были созданы или изменены в архивируемом change.
Для новых тематик Архиватор MUST добавить строку в INDEX.md и предложить
domain placement на основе Purpose из spec.md.

#### Scenario: Обновление существующей тематики
- **WHEN** архивируется change, затронувший spec.md существующей тематики
- **THEN** Архиватор обновляет соответствующий `topics/<topic>.yaml`
  (файлы, роли, entry points, тесты)

#### Scenario: Добавление новой тематики
- **WHEN** архивируется change, создавший новый spec.md
- **THEN** Архиватор создаёт `topics/<topic>.yaml`,
  добавляет строку в таблицу Topics в INDEX.md
  и предлагает размещение по доменам на основе Purpose
