## Why

При парном программировании с AI Эксперт планирует change (proposal → spec →
design → tasks), а Разработчик реализует. AI-агент Эксперта к концу
планирования накапливает «горячий кеш»: какие файлы читал, какие паттерны
увидел, как связаны части системы. Артефакты планирования сериализуют
**решения**, но не **контекст обнаружения**. При handoff Разработчику кеш
теряется: AI-агент Разработчика восстанавливает карту территории заново —
ищет файлы, читает их, строит понимание ролей. Это финансовые потери (токены)
и риск «не тот паттерн / не тот файл».

Нужен опциональный артефакт, сериализующий кеш Эксперта, и команда для его
создания перед handoff.

Тип: чистый tooling (новая capability + изменение существующей).

## What Changes

- Появляется артефакт `terra.md` в каталоге change — опциональная карта
  территории, составленная AI-агентом Эксперта. Содержит: карту файлов
  (путь, роль в change, действие), наблюдения Эксперта о коде, файлы-образцы
  паттернов, порядок чтения для углубления.
- Появляется Cursor-команда `/opsx-terra-firma`: формирует `terra.md` из
  текущего контекста AI-агента после завершения `tasks.md`. Запускается
  Экспертом перед handoff Разработчику.
- `terra.md` не входит в цепочку артефактов OpenSpec (proposal → spec →
  design → tasks). Это дополнительный файл, создаваемый командой, а не
  скиллом или CLI.
- Guidance для apply: AI-агент Разработчика читает `terra.md`, если он
  существует в change, перед выполнением задач.
- `terra.md` включается Экспертом в коммит — ответственность за передачу
  контекста лежит на Эксперте. Если файл отсутствует, apply работает как
  сейчас (кеш формируется заново).

## Capabilities

### New Capabilities
- `terra`: опциональный артефакт `terra.md` — сериализованный кеш
  исследования кодовой базы, передаваемый от AI-агента Эксперта к AI-агенту
  Разработчика при парном программировании.

_(нет изменений spec-level требований существующих capabilities)_

## Impact

- Новый файл: `.cursor/commands/opsx-terra-firma.md` (процедура создания
  `terra.md`).
- Правка: `openspec/config.yaml` (`operations.apply.guidance` — чтение
  `terra.md`).
- Новый spec: `openspec/specs/terra/spec.md`.
- Не трогать: `.cursor/skills/openspec-*`, `.cursor/commands/opsx-apply.md`,
  `.cursor/commands/opsx-archive.md` и прочие сгенерированные opsx-артефакты.
- Зависимости: нет новых пакетов.
- Runtime приложения не затрагивается.
