## Purpose

Сериализованный кеш исследования кодовой базы, передаваемый от AI-агента
Эксперта к AI-агенту Разработчика при парном программировании с AI.

## ADDED Requirements

### Requirement: Опциональность terra.md
`terra.md` MUST быть опциональным. Если файл отсутствует в change, apply
MUST работать штатно — AI-агент Разработчика формирует контекст
самостоятельно.

#### Scenario: Apply без terra.md
- **WHEN** AI-агент Разработчика начинает apply
- **AND** `terra.md` отсутствует в каталоге change
- **THEN** apply выполняется штатно, без ошибок

#### Scenario: Apply с terra.md
- **WHEN** AI-агент Разработчика начинает apply
- **AND** `terra.md` присутствует в каталоге change
- **THEN** AI-агент читает `terra.md` перед выполнением задач

### Requirement: Содержание terra.md — необходимое и достаточное
`terra.md` MUST содержать информацию, достаточную для того, чтобы AI-агент
Разработчика мог начать выполнение каждой задачи из `tasks.md` без поисковых
операций по репозиторию. Информация MUST быть необходимой: каждое утверждение
устраняет конкретный cache miss (поиск, угадывание или ошибочное действие).

Критерии содержания:

1. **Карта файлов**: для каждого файла, затронутого или влияющего на change —
   путь, роль в этом change, действие (создать / изменить / читать как
   образец / не трогать).
2. **Наблюдения**: факты о коде, обнаруженные Экспертом и повлиявшие на
   решения в design — конкретные структуры, форматы, соглашения.
3. **Образцы**: если change MUST следовать существующему паттерну — конкретный
   файл-образец и что именно в нём является паттерном.
4. **Навигация**: порядок чтения файлов от общего к частному для углубления
   в контекст.

#### Scenario: Достаточность — AI-агент не ищет файлы
- **WHEN** AI-агент Разработчика читает terra.md
- **AND** берёт любую задачу из tasks.md
- **THEN** AI-агент знает какие файлы открыть для выполнения задачи
- **AND** не выполняет поисковые операции по репозиторию для их обнаружения

#### Scenario: Достаточность — AI-агент знает паттерн
- **WHEN** задача из tasks.md требует следовать существующему паттерну
- **AND** terra.md содержит образец этого паттерна
- **THEN** AI-агент следует указанному образцу
- **AND** не угадывает формат или стиль самостоятельно

#### Scenario: Необходимость — нет лишней информации
- **WHEN** утверждение из terra.md удалено
- **AND** это не вызывает у AI-агента Разработчика поиск, угадывание
  или ошибочное действие
- **THEN** это утверждение было лишним и не должно было быть в terra.md

### Requirement: Создание terra.md командой /opsx-terra-firma
`terra.md` MUST создаваться командой `/opsx-terra-firma`, а не вручную или
другим скиллом. Команда MUST быть доступна только после завершения `tasks.md`
в том же контексте (сессии AI-агента Эксперта).

#### Scenario: Эксперт запускает /opsx-terra-firma после tasks
- **WHEN** Эксперт завершил планирование (tasks.md создан)
- **AND** запускает `/opsx-terra-firma`
- **THEN** AI-агент создаёт `terra.md` в каталоге change

#### Scenario: Предупреждение без tasks.md
- **WHEN** Эксперт запускает `/opsx-terra-firma`
- **AND** `tasks.md` ещё не создан
- **THEN** AI-агент предупреждает, что планирование не завершено

### Requirement: terra.md не входит в цепочку артефактов OpenSpec
`terra.md` MUST NOT быть частью цепочки артефактов OpenSpec (proposal → spec →
design → tasks). CLI MUST NOT валидировать или отслеживать `terra.md`.
Файл создаётся командой и коммитится Экспертом.

#### Scenario: openspec validate игнорирует terra.md
- **WHEN** выполняется `openspec validate`
- **THEN** наличие или отсутствие `terra.md` не влияет на результат валидации

#### Scenario: openspec status игнорирует terra.md
- **WHEN** выполняется `openspec status`
- **THEN** `terra.md` не отображается в списке артефактов

### Requirement: Ответственность Эксперта
Включение `terra.md` в коммит — ответственность Эксперта. AI-агент
MUST NOT создавать `terra.md` автоматически при archive или apply.

#### Scenario: Archive без terra.md
- **WHEN** Эксперт архивирует change
- **AND** `terra.md` не был создан
- **THEN** archive выполняется штатно

#### Scenario: Apply не создаёт terra.md
- **WHEN** AI-агент Разработчика выполняет apply
- **THEN** он MUST NOT создавать или изменять `terra.md`

### Requirement: Guidance для apply
`operations.apply.guidance` в `openspec/config.yaml` MUST содержать указание
читать `terra.md` при его наличии в change.

#### Scenario: Apply guidance упоминает terra.md
- **WHEN** AI-агент читает apply guidance из config.yaml
- **THEN** он получает указание прочитать `terra.md` если файл существует
