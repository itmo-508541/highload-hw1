## MODIFIED Requirements

### Requirement: INDEX.md — компактная точка входа
INDEX.md MUST содержать:
- Таблицу доменов (domain, description, topics).
- Таблицу тематик (topic, spec path, summary — краткое описание в свободной форме).

#### Scenario: Агент ориентируется по INDEX.md
- **WHEN** агент читает INDEX.md
- **THEN** он получает полный перечень доменов и тематик за одно чтение файла

### Requirement: Агент — read-only потребитель
AI-агент MUST использовать индекс только для чтения, кроме исполнения
команды `/opsx-index`. Обновление индекса — ответственность Архиватора
(человека): он запускает `/opsx-index` и при отсутствии контекста реализации
указывает коммиты, которыми change был реализован.

#### Scenario: Агент не модифицирует индекс вне /opsx-index
- **WHEN** агент работает с проектом не в рамках команды `/opsx-index`
- **THEN** он НЕ создаёт и НЕ изменяет файлы в директории скилла capability-index

#### Scenario: Агент обновляет индекс по /opsx-index
- **WHEN** Архиватор запускает `/opsx-index` для допустимого архивированного change
- **THEN** агент создаёт или изменяет соответствующие файлы индекса

## REMOVED Requirements

### Requirement: Инкрементальное обновление при archive
**Reason**: Индексация больше не выполняется в ходе archive; Архиватор
запускает её вручную командой `/opsx-index`.
**Migration**: После archive использовать `/opsx-index` с именем папки архива.

## ADDED Requirements

### Requirement: Инкрементальное обновление командой /opsx-index
Индекс MUST обновляться только по команде `/opsx-index` и только для change,
уже лежащего в архиве. Команда MUST отвергать незаархивированный change.
Индексация MUST быть запрещена, если у архива нет изменений spec
(`openspec/specs/`). Если в архиве несколько spec.md, команда MUST
проиндексировать их все.

Обновление MUST быть слиянием, не заменой файла: записи этого change
вливаются и при необходимости обновляются по текущему main spec; записи,
которых этот change не касался, MUST сохраняться. Повторный запуск по тому
же архиву MUST обновлять те же тематики тем же слиянием.

Если в текущем чате уже есть картина реализации, агент MUST использовать её.
Если картины нет, агент MUST запросить у Архиватора коммиты реализации и
MUST NOT самостоятельно искать их в git-истории; писать индекс MUST NOT,
пока коммиты не указаны.

После успешного archive Архиватору MUST напомнить запустить `/opsx-index`
для только что архивированного change.

#### Scenario: Индексация архивированного change
- **WHEN** Архиватор запускает `/opsx-index` для change в каталоге архива
- **AND** в архиве есть изменённые или новые spec.md
- **THEN** агент обновляет topic-файлы всех затронутых тематик

#### Scenario: Отказ для незаархивированного change
- **WHEN** цель `/opsx-index` не находится в архиве
- **THEN** индексация не выполняется
- **AND** Архиватору сообщается отказ

#### Scenario: Отказ без изменений spec
- **WHEN** в архиве нет spec.md (нет изменений в `openspec/specs/`)
- **THEN** индексация не выполняется
- **AND** Архиватору сообщается отказ

#### Scenario: Несколько spec в одном change
- **WHEN** архив содержит более одного spec.md
- **THEN** команда индексирует каждую затронутую тематику

#### Scenario: Слияние с существующим topic-файлом
- **WHEN** для тематики уже есть `topics/<topic>.yaml`
- **THEN** записи этого change вливаются или обновляются по текущему main spec
- **AND** записи, которых этот change не касался, остаются

#### Scenario: Добавление новой тематики
- **WHEN** архивированный change создал новый spec.md
- **THEN** создаётся `topics/<topic>.yaml`
- **AND** в INDEX.md появляется строка тематики
- **AND** размещение по доменам берётся из Purpose spec.md

#### Scenario: Повторный запуск переиндексирует
- **WHEN** Архиватор снова запускает `/opsx-index` для того же архива
- **THEN** те же тематики обновляются слиянием
- **AND** topic-файл не заменяется целиком

#### Scenario: Контекст чата используется без запроса коммитов
- **WHEN** в текущем чате уже есть картина реализации change
- **THEN** агент использует этот контекст
- **AND** не обязан запрашивать коммиты

#### Scenario: Без контекста агент запрашивает коммиты
- **WHEN** картины реализации в чате нет
- **THEN** агент запрашивает у Архиватора коммиты реализации
- **AND** не ищет их самостоятельно в git-истории
- **AND** не пишет индекс, пока Архиватор не укажет коммиты

#### Scenario: Напоминание после archive
- **WHEN** archive change завершён успешно
- **THEN** Архиватору сообщают о необходимости запустить `/opsx-index`
  для этого архива
