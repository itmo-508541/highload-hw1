## Purpose

HTTP-хранилище записей «ключ — значение»: клиент создаёт запись со скалярным
значением, получает её целочисленный id, читает и заменяет значение по этому id.

## ADDED Requirements

### Requirement: Создание записи
Сервис SHALL по запросу `POST /items` с валидным телом (см. требование
«Тело запроса записи») сохранять запись и отвечать кодом `201` с JSON-объектом
`{"id": N}`, где `N` — положительное целое число. Каждый успешный `POST /items`
MUST выдавать id, не совпадающий ни с одним ранее выданным, в том числе когда
записи создаются через разные экземпляры сервиса, работающие с одним
хранилищем.

#### Scenario: Успешное создание
- **WHEN** клиент отправляет `POST /items` с телом `{"value": "foo"}`
- **THEN** ответ имеет код `201`
- **AND** тело ответа — JSON-объект с единственным ключом `id`, значение
  которого — положительное целое число

#### Scenario: Два создания дают разные id
- **WHEN** клиент дважды отправляет `POST /items` с одинаковым телом
- **THEN** оба ответа имеют код `201`
- **AND** id в ответах различаются

#### Scenario: Созданная запись видна через другой экземпляр
- **WHEN** запись создана через один экземпляр сервиса
- **THEN** `GET /items/{id}` к другому экземпляру, работающему с тем же
  хранилищем, возвращает её значение

### Requirement: Чтение записи
Сервис SHALL по запросу `GET /items/{id}` для существующей записи отвечать
кодом `200` с JSON-объектом `{"value": X}`, где `X` совпадает с последним
записанным значением по значению и по JSON-типу. Для id, под которым записи
нет, а также для id, не являющегося положительным целым числом, сервис MUST
отвечать кодом `404`.

#### Scenario: Чтение созданной записи
- **WHEN** запись создана телом `{"value": "foo"}` и получила id `N`
- **AND** клиент отправляет `GET /items/N`
- **THEN** ответ имеет код `200`
- **AND** тело ответа — `{"value": "foo"}`, других ключей нет

#### Scenario: Тип значения сохраняется
- **WHEN** записи созданы со значениями `"1"`, `1`, `1.5`, `true`, `false`
  и `""`
- **THEN** `GET` каждой из них возвращает значение того же JSON-типа и с тем же
  значением, что было отправлено

#### Scenario: Несуществующий id
- **WHEN** клиент отправляет `GET /items/{id}` с id, под которым записи нет
- **THEN** ответ имеет код `404`

#### Scenario: id не является числом
- **WHEN** клиент отправляет `GET /items/abc`
- **THEN** ответ имеет код `404`

### Requirement: Замена значения записи
Сервис SHALL по запросу `PUT /items/{id}` с валидным телом для существующей
записи заменять её значение и отвечать кодом `200` с JSON-объектом
`{"id": N}`, где `N` — id из пути. Для id, под которым записи нет, сервис MUST
отвечать кодом `404` и MUST NOT создавать запись. Для id, который не является
положительным целым числом из диапазона id, выдаваемых сервисом, сервис MUST
отвечать кодом `404` независимо от тела запроса.

#### Scenario: Замена значения
- **WHEN** запись с id `N` существует
- **AND** клиент отправляет `PUT /items/N` с телом `{"value": 42}`
- **THEN** ответ имеет код `200`, тело — `{"id": N}`
- **AND** последующий `GET /items/N` возвращает `{"value": 42}`

#### Scenario: Замена несуществующей записи
- **WHEN** клиент отправляет `PUT /items/{id}` с валидным телом и id, под
  которым записи нет
- **THEN** ответ имеет код `404`
- **AND** последующий `GET` по этому id тоже отвечает `404`

#### Scenario: Замена по id, не являющемуся числом
- **WHEN** клиент отправляет `PUT /items/abc` с телом `{}`
- **THEN** ответ имеет код `404`

### Requirement: Тело запроса записи
Тело запросов `POST /items` и `PUT /items/{id}` MUST быть JSON-объектом ровно
с одним ключом `value`, значение которого — строка (в том числе пустая),
целое число, дробное число или `true`/`false`. На любое другое тело сервис MUST
отвечать кодом `400` и MUST NOT изменять хранилище. Другим телом считается и
тело, отправленное не с заголовком `Content-Type: application/json`, и число,
не представимое конечным значением. Для `PUT` по id из диапазона id,
выдаваемых сервисом, проверка тела SHALL выполняться независимо от
существования записи: невалидное тело даёт `400`, даже если записи с таким id
нет.

#### Scenario: Нет ключа value
- **WHEN** клиент отправляет `POST /items` с телом `{}`
- **THEN** ответ имеет код `400`

#### Scenario: Лишний ключ
- **WHEN** клиент отправляет `POST /items` с телом `{"value": 1, "extra": 2}`
- **THEN** ответ имеет код `400`

#### Scenario: Значение null
- **WHEN** клиент отправляет `POST /items` с телом `{"value": null}`
- **THEN** ответ имеет код `400`

#### Scenario: Значение — массив или объект
- **WHEN** клиент отправляет `POST /items` с телом `{"value": [1]}` или
  `{"value": {"a": 1}}`
- **THEN** ответ имеет код `400`

#### Scenario: Невалидный JSON
- **WHEN** клиент отправляет `POST /items` с телом, которое не разбирается как
  JSON
- **THEN** ответ имеет код `400`

#### Scenario: Тело не в формате JSON
- **WHEN** клиент отправляет `POST /items` с телом `value=foo` и заголовком
  `Content-Type: application/x-www-form-urlencoded`
- **THEN** ответ имеет код `400`

#### Scenario: Число вне диапазона
- **WHEN** клиент отправляет `POST /items` с телом `{"value": 1e400}`
- **THEN** ответ имеет код `400`

#### Scenario: Невалидное тело не меняет запись
- **WHEN** запись с id `N` имеет значение `"foo"`
- **AND** клиент отправляет `PUT /items/N` с телом `{"value": null}`
- **THEN** ответ имеет код `400`
- **AND** последующий `GET /items/N` возвращает `{"value": "foo"}`

#### Scenario: Невалидное тело при несуществующей записи
- **WHEN** клиент отправляет `PUT /items/{id}` с телом `{}` и id, под которым
  записи нет
- **THEN** ответ имеет код `400`

### Requirement: Формат ответов и доступ
Ответы ручек `/items` и `/items/{id}`, включая ответы с кодами ошибок, MUST
иметь JSON-тело и заголовок `Content-Type: application/json` независимо от
заголовка `Accept` запроса. Ручки MUST быть доступны без аутентификации.

#### Scenario: Ошибка отдаётся в JSON
- **WHEN** клиент отправляет `GET /items/{id}` с несуществующим id и
  заголовком `Accept: */*`
- **THEN** ответ имеет код `404`
- **AND** `Content-Type` ответа — `application/json`, тело — JSON-объект

#### Scenario: Запрос без учётных данных
- **WHEN** клиент отправляет `POST /items` с валидным телом без заголовков
  аутентификации
- **THEN** ответ имеет код `201`
