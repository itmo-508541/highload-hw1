# Proposal

**Тип:** новая capability; попутно — правка формулировок спеки `qa` и
описательной документации без изменения поведения.

## Why

Домашнее задание HW1 (`HW1.md`, «Подготовительная часть») требует микросервис
ровно с тремя REST-ручками над записями и служебной ручкой готовности. На этом
сервисе строятся следующие части работы: метрики золотых сигналов, генератор
дашборда, нагрузочный скрипт. В шаблоне такого приложения нет. С этим change
репозиторий перестаёт быть шаблоном и становится приложением «Инструменты
автоматизации в Grafana», а описательная документация должна это отражать.

Задание предлагает in-memory хранилище, но под PHP-FPM каждый запрос живёт
в своём процессе, и данные рантайма между запросами не сохраняются. Поэтому
записи хранятся в Redis, который в стеке уже есть. Отход от текста задания
фиксируется в ADR.

## What Changes

- Ручка `POST /items`: создаёт запись из тела `{"value": <скаляр>}`, выдаёт
  новый целочисленный id и отвечает `201 {"id": N}`.
- Ручка `GET /items/{id}`: отвечает `200 {"value": X}` — тем значением и того
  типа, которые были записаны; для несуществующего id — `404`.
- Ручка `PUT /items/{id}`: заменяет значение существующей записи из тела
  `{"value": <скаляр>}` и отвечает `200 {"id": N}`; для несуществующего id —
  `404` (upsert не выполняется).
- Тело POST и PUT содержит ровно один ключ `value` со скалярным значением
  (строка, целое, дробное, bool). Отсутствие ключа, лишние ключи, `null`,
  массив, объект, невалидный JSON, тело не с `Content-Type: application/json`
  или число вне диапазона (`1e400`) — `400`.
- Служебная ручка `GET /health`: `200`, когда сервис готов принимать запросы,
  то есть хранилище отвечает; иначе `503`.
- Ответы ручек `/items` и `/health`, включая ошибки, — JSON. Ручки доступны без
  аутентификации.
- ADR о хранении записей в Redis вместо in-memory.
- Описательные места документации, где репозиторий назван шаблоном,
  переписываются: проект описан как приложение «Инструменты автоматизации
  в Grafana». Технические разделы (стек, команды, constraints, каталоги,
  скиллы) сохраняются.
- Формулировки spec `qa` «Шаблон MUST …» становятся «Проект MUST …».
  Поведение, которое они требуют, не меняется.

## Capabilities

### New Capabilities

- `items`: CRUD над записями «ключ — значение» по HTTP: создание, чтение,
  замена значения, формат тела и ответов, коды ошибок.
- `health`: служебная ручка готовности сервиса к приёму запросов.

### Modified Capabilities

- `qa`: только формулировки — субъект требований «шаблон» заменяется на
  «проект», требование «PHPUnit и Behat как обязательные QA-инструменты
  шаблона» переименовывается. Нормативное содержание и сценарии те же.

Spec `platform` упоминает шаблон только в `Purpose`; его требования не
меняются, поэтому delta нет — `Purpose` правится в основной спеке напрямую,
как и `Purpose` спеки `qa`.

## Impact

- **Код:** контроллеры `src/Controller/Item/` (создание, чтение, замена) и
  `src/Controller/HealthController.php` — по одному классу с `__invoke` на
  ручку; модели ответов в `App\Model\Rest`; хранилище записей поверх
  существующего сервиса `Redis`.
- **Конфигурация:** правило `format_listener` в `config/packages/fos_rest.yaml`
  для путей `/items` и `/health`, чтобы ответы и ошибки отдавались в JSON.
- **Тесты:** приёмочные сценарии Behat новых доменов `item_storage`
  и `service_health`; сессия Behat без браузера (`symfony`) в
  `behat.yml.dist`; реестр доменов и таблица сессий в `features/CLAUDE.md`;
  отдельная БД Redis для test-окружения в `.env.test`; правило размещения
  шагов и исключение уборки (`@BeforeScenario` для тестовой БД Redis)
  в `features/CLAUDE.md` и ADR 0002.
- **Документация контура Redis:** `docs/runbooks/redis.md` — ключи
  `items:seq`, `item:{id}`, тестовая БД; ADR 0004.
- **API:** новые публичные пути `/items`, `/items/{id}`, `/health` вне
  префикса `/api` и вне JWT-firewall.
- **Данные:** ключи `items:seq` и `item:{id}` в Redis (том `redis-data`).
- **Документация** — описательные места, где проект назван шаблоном:
  - `README.md`: заголовок, вводный абзац, строка `ABOUT.md` в таблице
    «Документация»;
  - `ABOUT.md`: заголовок; разделы «Шаблон: …» и HTML-комментарий
    о сопровождении шаблона удаляются; заглушки заполняются описанием
    приложения и HW1;
  - `CLAUDE.md`: заголовок и вводный абзац о шаблоне;
  - `docs/CLAUDE.md`: «Поведение продукта/шаблона»;
  - `docs/runbooks/e2e.md`: «Harness шаблона»;
  - `.claude/skills/vendor-class-lookup/README.md`: «в шаблоне зафиксированы»,
    «В шаблоне флаг включён»;
  - `features/admin_access_anonymous_entry.feature`: повествование `Feature`
    («границу аутентификации шаблона»), шаги не меняются;
  - новый ADR в `docs/adr/`.
- **OpenSpec:** `context` в `openspec/config.yaml` («шаблон, приложения нет»);
  `Purpose` основных спек `platform` и `qa`; delta-спека `qa`.
- **Вне объёма:** слово «шаблон» в другом смысле — шаблон пути или поиска
  (`CLAUDE.md` про `rg`, `HW1.md`), шаблоны секретов (`secrets/`), шаблон
  блока в скилле `add-docker-volume`, шаблонные значения `.env`
  (`docs/runbooks/dotenv.md`), шаблон скилла в ADR 0003.
- **Зависимости:** dev-зависимость `behat/mink-browserkit-driver` — драйвер
  сессии Behat без браузера; в production новых зависимостей нет.
