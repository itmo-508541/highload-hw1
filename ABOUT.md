## Шаблон: проблема и цель

Командам нужна **повторяемая основа** для backend на Symfony: единое локальное
окружение (Docker), согласованный цикл разработки и проверок (Makefile, QA),
понятный деплой (GitLab CI/CD) и **единый процесс изменений** (OpenSpec:
explore → propose → apply → archive), без расхождения «на хосте у меня работает»
с CI и продом.

**Цель шаблона** — дать готовую точку входа: стек PHP 8.4 / Symfony 7.4, MySQL 8,
Redis 8, Composer, Phing, QA (PHP CS Fixer, PHPStan, Rector, PHPUnit, Behat),
работу только в контейнере `php`, плюс артефакты OpenSpec в git и job
`qa:openspec` в CI. Подробно для людей — `README.md` и `openspec/process.md`.
Доменная логика в шаблон **намеренно не вписана** — разделы без префикса
«Шаблон:» ниже и specs по мере реальных changes.

---

## Шаблон: ограничения и допущения

- Команды, затрагивающие PHP и экосистему Symfony/Composer/QA, выполняются **только** в сервисе `php` (см. `README.md`); на хосте из корня репозитория их не запускаем.
- Секреты production не хранятся в репозитории; реальные значения — в CI и/или серверном окружении.
- Ограничения и допущения **конкретного продукта** (SLA, интеграции, compliance) фиксируются в разделе «Ограничения и допущения» ниже.

## Ключевые компоненты и технологии

| Область | Содержание |
|--------|------------|
| Runtime | PHP 8.4, Symfony 7.4.* |
| Данные | MySQL 8.0 и Redis 8 |
| Окружение | Docker / Docker Compose, сервис `php`; команды PHP/Composer/QA — в контейнере |
| Сборка и задачи | Composer, Phing (`make init` и связанные цели) |
| Качество | PHP CS Fixer, PHPStan, Rector, PHPUnit, Behat (`make qa` и отдельные цели) |
| Деплой | GitLab CI/CD (как настроено в репозитории) |
| AI / процесс | OpenSpec ([`openspec/process.md`](openspec/process.md)): explore → propose → apply → archive; Cursor `/opsx-*`; ADR через `/adr` → `adr/`; PHP/QA только в Docker |

Детали команд — `README.md` / `Makefile`. Поведение — `openspec/specs/`.
Деплой — [`DEPLOYMENT.md`](DEPLOYMENT.md).
