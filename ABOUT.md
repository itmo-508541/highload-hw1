# Symfony backend

Этот файл задаёт **два уровня контекста**:

1. **Разделы с префиксом «Шаблон:»** — зачем существует эта стартовая точка и какие рамки зафиксированы стеком и инфраструктурой (относится к репозиторию-шаблону).
2. **Разделы второго уровня без префикса** — описание конкретного продукта: их нужно **заполнить или заменить** после создания нового репозитория на основе шаблона, чтобы команда и инструменты планирования опирались на домен, а не на заглушки.

**После форка:** задайте свой заголовок `#` в начале файла и удалите всё от первого `## Шаблон:` до конца HTML-комментария ниже (включительно) — дальше останется только продуктовое описание, **без** снятия префиксов в заголовках.

Подробности запуска, команд и переменных окружения — в `README.md`.

## Шаблон: проблема и цель

Командам нужна **повторяемая основа** для backend на Symfony: единое локальное окружение (Docker), согласованный цикл разработки и проверок (Makefile, QA), понятный деплой (GitLab CI/CD), без расхождения «на хосте у меня работает» с CI и продом.

**Цель шаблона** — дать готовую точку входа: стек PHP 8.4 / Symfony 7.4, MySQL 8, Composer, Phing, инструменты качества (PHP CS Fixer, PHPStan, Rector, PHPUnit, Behat) и правила работы только в контейнере `php`. Подробно для людей это изложено в `README.md`. Для агента Cursor перечислены обязательные **skills** (в т.ч. запуск команд в Docker) в `.cursor/rules/skills.mdc` — там нет дублирования текста из README, только отсылки на нужные скиллы. Доменная бизнес-логика и продуктовые сценарии в шаблон **намеренно не вписаны** — их описывают разделы без префикса «Шаблон:» ниже.

---

## Шаблон: ограничения и допущения

- Команды, затрагивающие PHP и экосистему Symfony/Composer/QA, выполняются **только** в сервисе `php` (см. `README.md`); на хосте из корня репозитория их не запускаем.
- Секреты production не хранятся в репозитории; реальные значения — в CI и/или серверном окружении.
- После работы в контейнере от `root` возможны файлы с владельцем `root` на хосте — для выравнивания используется `make owner` (см. `README.md`).
- Ограничения и допущения **конкретного продукта** (SLA, интеграции, compliance) фиксируются в разделе «Ограничения и допущения» ниже.

| Область | Содержание |
|--------|------------|
| Runtime | PHP 8.4, Symfony 7.4.* |
| Данные | MySQL 8.0; миграции Doctrine — по договорённостям проекта (см. `README.md` про схему и данные) |
