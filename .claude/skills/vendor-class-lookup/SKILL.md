# Поиск определения класса

## Когда вызывать

Вызывать, как только встретился FQCN или короткое имя класса, чьё определение
не прочитано в этой сессии, и предстоит что-то сделать с его API: вызвать метод,
унаследоваться, переопределить, передать аргумент. Расположение класса значения
не имеет — `vendor/` и `src/` равно подходят, и выяснится оно только в результате
поиска.

Не вызывать: определение уже прочитано в этой сессии; класс написан здесь же
и целиком виден.

## Правило

**Неймспейс, сигнатуру и состав методов брать из файла под `vendor/`, версию
пакета — из `composer.lock`. Не по памяти:** версии здесь свежее знания модели
(PHP 8.4, Symfony 7.4, Doctrine ORM 3.6, PHPUnit 13, Sonata Admin 4.43), и
восстановленный по памяти API даёт неверные неймспейсы, сигнатуры прошлого
мажора и методы, которые к этой версии уже удалены.

Версия пакета:

```bash
grep -A1 '"name": "sonata-project/admin-bundle"' composer.lock
```

## Ловушка: `vendor/` под `.gitignore`

`/vendor/` перечислен в `.gitignore`, и поиск, уважающий `.gitignore`, молча его
не видит: возвращает **пустой результат с кодом успеха**, а не ошибку.

**Пустой результат поиска не означает, что класса нет.**

Обход — передавать `vendor/` **явным путём** в аргументах: правила игнорирования
применяются при обходе дерева, а не к пути, заданному явно.

```bash
rg -n "class AbstractAdmin" vendor/
```

Ничего не найдено — повторить с отключённым фильтром, и только потом делать
выводы:

```bash
rg -n --no-ignore "class AbstractAdmin" vendor/
```

В shell, где `grep` подменён обёрткой, системный вариант — `command grep -rn
"class AbstractAdmin" vendor/`.

## Рабочий цикл

Пути — от корня проекта.

1. **PSR-4 — `vendor/composer/autoload_psr4.php`.** Найти самый длинный
   совпадающий с FQCN префикс; значение — корневой каталог; остаток FQCN
   превращается в `Foo/Bar.php`. Для `App\…` брать префиксы из `composer.json`,
   секции `autoload` и `autoload-dev`.
2. **Классмап — `vendor/composer/autoload_classmap.php`,** если PSR-4 не дал
   ответа. Ключи в одинарных кавычках, `\` записан как `\\`. Путь — в значении
   после `$vendorDir . '` для зависимости или `$baseDir . '` для кода проекта.
   Классмап в проекте неполон (`optimize-autoloader` не включён), поэтому пусто
   в нём ничего не доказывает.
3. **Сузить область — `composer.lock`.** `packages[].name` → ожидаемый каталог
   `vendor/<vendor>/<package>/`. Только чтобы уточнить поиск по autoload-файлам;
   перебирать файлы пакета руками не нужно.
4. **Один раз прочитать файл** по полученному пути.

Путь берётся только из артефактов, сгенерированных Composer. Не выдумывать путь
и не обходить `vendor/` рекурсивно вместо шагов 1–3.

## Стоп

Путь не разрешился либо файла по нему нет — **остановиться и спросить
пользователя.** Сообщить: искомый FQCN, что показали autoload-файлы, и что,
вероятно, нужна установка зависимостей. Не уходить в веб, не начинать
разведочный обход каталогов.

Пересборка автолоадера, как и любые другие PHP-команды, — только внутри
контейнера:

```bash
docker compose exec php composer dump-autoload
```

## Веб

При установленных зависимостях определение класса читается локально, не с GitHub.
Веб оправдан в двух случаях: нужна документация или changelog; пакет в проекте
не установлен и локального источника нет.
