# COLLECT — обновление Model Knowledge Patch для текущей версии PHPUnit

Эта инструкция описывает процесс обновления дельта-патча (например, `PHPUnit13.md`) при переходе на новую минорную версию PHPUnit.

## Когда запускать

Пользователь обновил содержимое директории `PHPUnit13/` (ChangeLogs, DEPRECATIONS) после перехода на новую минорную версию и просит обновить Knowledge Patch.

## Входные данные

- Файлы в директории `PHPUnit13/` — ChangeLogs и DEPRECATIONS актуальной версии.
- Текущий файл `PHPUnit13.md` — дельта-патч, который нужно **дополнить** (не переписать).

## Задача

Дополни файл `PHPUnit13.md` новыми знаниями из обновлённых исходников в `PHPUnit13/`.

Результат — цельный файл, который выглядит так, будто сразу создан для текущей минорной версии. Не должно быть видно «швов» между старым и новым содержимым.

## Принципы составления

Принципы записаны в заголовке целевого файла (под `# PHPUnit 13 — Model Knowledge Patch`). Кратко:

- Формат «Do not write → Write instead» — модель должна немедленно понять, что заменить.
- Только факты, меняющие код `*Test.php`. CLI, XML-конфиг, PHAR, логгеры — вне скоупа.
- Не включать то, что модель и так знает правильно (тратит токены без пользы).
- Если deprecated API не выбрасывает runtime warning — указать явно.
- Каждый пункт — самодостаточный; порядок чтения не важен.
- Писать на английском (кроме описания принципов).

## Что включать

- Новые assertions и методы API, о которых модель может не знать.
- Удалённые или переименованные методы/классы, которые модель может использовать по привычке.
- Новые deprecations (с пометкой `hard deprecated` или `soft deprecated, no runtime warning`).
- Изменения поведения, на которые модель могла полагаться.

## Что НЕ включать

- Bugfixes — они не меняют набор доступных API и не влияют на выбор модели при написании тестов.
- Изменения CLI, конфигурации XML, логгеров, PHAR-дистрибуции.
- То, что уже есть в файле (не дублировать).
- То, что модель и так знает правильно.

## Порядок действий

1. Прочитай текущий `PHPUnit13.md` целиком.
2. Прочитай все файлы в `PHPUnit13/`.
3. Выдели изменения, которые проходят фильтр (см. «Что включать»).
4. Допиши новые пункты в соответствующие секции `PHPUnit13.md`:
   - `## Banned calls → replacements` — таблица.
   - `## Assertions the model may not know about` — список.
   - `## Behavior traps` — список.
   - `## Test structure` — список.
5. Убедись, что файл выглядит цельным и не содержит дублей.
