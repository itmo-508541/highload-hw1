# ADR-0001: ADR через `/adr` в каталоге `adr/` рядом с OpenSpec

## Статус

Принято

## Дата

2026-08-01

## Контекст

В репозитории внедрён процесс OpenSpec (профиль `core`, схема `spec-driven`).
Нужно зафиксировать, как вести долгоживущие архитектурные решения относительно
change-артефактов. Stock-схема `spec-driven` не содержит артефакта `adr`.
Community-схема `intent-driven` добавляет change-local `adr.md` и durable ADR в
корневом `adr/`, но меняет формат specs на Gherkin `GIVEN`/`WHEN`/`THEN` и
запрещает правки раздела Status у принятых ADR. В проекте уже есть русскоязычный
шаблон ADR и правило иммутабельности с допустимым обновлением только «Статус».

## Решение

Оставляем команду Cursor `/adr` как механизм создания ADR. Канонический каталог
долгоживущих ADR — корневой `adr/` (рядом с `openspec/`, не внутри него). В
жизненном цикле OpenSpec change ADR появляется по необходимости после
`design.md` и до или во время `tasks.md` через задачу в чеклисте и правило в
`openspec/config.yaml`. ADR не обязателен для каждого мелкого change. Схему
OpenSpec не меняем и не форкаем ради артефакта `adr`.

## Обоснование

Профиль `core` и простота старта важнее формального stage-gate на каждый change.
Русский шаблон и модель статусов (включая «Заменено ADR-NNNN» через правку
только «Статус») уже согласованы с командой. Community `intent-driven` тянет
лишнее opinionated поведение specs и конфликтует с правилом иммутабельности.
Свой schema fork даёт формальный артефакт, но повышает стоимость сопровождения
experimental schema API без выигрыша для шаблонного репозитория.

## Рассмотренные альтернативы

- **Community `intent-driven`.** Плюс: явный артефакт `adr` в цепочке и
  change-local manifest. Минус: смена формата specs, другой ADR-style и
  запрет правок Status; тяжелее для `core`-старта.
- **Свой fork `spec-driven` с артефактом `adr`.** Плюс: сохраняет WHEN/THEN и
  можно вписать русский шаблон. Минус: сопровождение локальной schema и
  обязательный `adr.md` на каждый change без существенной пользы поверх `/adr`.
- **Оставить ADR в `docs/adr/`.** Плюс: нулевой перенос. Минус: смешивает
  runbook'и `docs/` с логом решений; community и OpenSpec-документация ожидают
  durable ADR рядом с процессом, а не внутри операционных docs.

## Последствия

- Новые ADR создаются в `adr/NNNN-<slug>.md` командой `/adr`.
- `docs/adr/` содержит только указатель на канонический каталог.
- OpenSpec validate остаётся на stock `spec-driven`; CI не зависит от ADR-схемы.
- При желании позже усилить gate можно рассмотреть schema fork без смены
  канонического пути `adr/`.
